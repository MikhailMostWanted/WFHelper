## Что допускает GitHub

[Официальная инструкция GitHub](https://docs.github.com/en/pull-requests/how-tos/work-with-forks/detaching-a-fork) описывает **Settings → General → Danger Zone → Leave fork network**. Для кнопки нужны публичный форк меньше 1 ГБ и отсутствие дочерних форков. Текущие API-метаданные: public, `size=57435` KiB, child forks=0; доступность кнопки ещё нужно проверить в интерфейсе администратора.

Отделение необратимо. GitHub сохраняет метаданные Git-коммитов, но предупреждает о потере связанных issues, PR, wiki, stars, watchers, comments, child forks и другой repository metadata. Не следует обещать сохранение repository ID, release assets, настроек или прежних URL без отдельной проверки.

1. Зафиксировать все refs и полный bundle, проверить восстановление. Сохранить provenance, лицензии и собственные расходящиеся ветки.
2. Отдельно выгрузить release assets/notes/checksums, историю PR/комментариев и нужные настройки/hooks. Сейчас есть два merged PR и четыре собственных release: отсутствие звёзд и выключенные Issues не означает отсутствие ценной metadata.
3. Составить таблицу до/после: repository ID, имя, visibility, parent/fork, releases, PR, remotes, workflows, hooks, права и ссылки. Секретные значения не включать в публичную копию.
4. Представить владельцу конкретные последствия и резервные материалы. Только затем выполнять согласованное необратимое действие через поддерживаемый интерфейс.
5. После завершения повторить API-проверку `fork/parent`, проверить remotes, release downloads, настройки и ссылки. Обновить статус по наблюдаемому результату.

Если кнопка недоступна, следующий шаг — обращение к GitHub Support с сохранённой инвентаризацией. Удаление/создание репозитория заново здесь не подготовлено как автоматическая замена.
