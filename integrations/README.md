# WantedFrame → ChatGPT

Два режима: автономный ZIP `account.json` + `README_CHATGPT.md` или приватный MCP на VPS.
Это отдельный канал данных, а не передача пароля игры модели. Работающий рынок и источник инвентаря не заменяются.

## Что реализовано

Приложение строит разрешённый снимок, каталог разделов, даты и сведения о пропусках.
Из имеющихся данных экспортируются количества, экземпляры снаряжения, мод-конфигурации и ссылки,
ранги модов, мистификаторы, осколки, пресеты, исторический XP, производство, чертежи,
репутация, счётчики испытаний, навыки, Фокус, дневные остатки, дополнительное снаряжение,
привязанный кеш статистики профиля и игровой справочник с рецептами/компонентами/дропами.
Поддержка раздела не означает, что источник действительно его предоставил. `list_data_sections`
показывает `missing`/`partial`, доступные поля и время. Имена неизвестных коллекций передаются без содержимого.

У профиля собственная дата; он берётся ТОЛЬКО из существующего кеша и только после проверки,
что снимок инвентаря принадлежит тому же аккаунту. Новых вызовов приватного игрового API нет.
Справочник берётся из базы WantedFrame: дата его обновления в этом слое неизвестна. Боевая
симуляция урона НЕ реализована. Закодированные значения модов Разлома не названы процентами.

Новая кнопка в настройках открывает системное меню: ZIP, отправка сейчас, подключение, автосинхронизация,
отключение. Подключение требует файл pairing с явно подтверждённым HTTPS-хостом. После первой ручной
отправки привязанного аккаунта можно включить отправку изменений (не чаще раза в 5 минут).
По умолчанию сеть выключена. Таймаут/ошибка не удаляет последний снимок. Для подтверждённых источников смена аккаунта блокируется. У manual-импорта идентичность не проверена: сравнение снимков для него отключено.
Импорты без доказанной привязки имеют bindingId=manual и могут передаваться только вручную.

## Быстрый локальный запуск для разработчика

Из корня репозитория:

```sh
python -m venv .venv
.venv/bin/python -m pip install './integrations[test]'
.venv/bin/wantedframe-mcp import --data /tmp/wantedframe-demo --input /path/to/WantedFrame-ChatGPT.zip
.venv/bin/wantedframe-mcp overview --data /tmp/wantedframe-demo
```

Для публичного сервера нужен отдельный GitHub OAuth App; callback `https://YOUR_HOST/auth/callback`.
Точный callback ChatGPT в настройках MCP отличается от callback GitHub: в `redirectUris` нужен
именно URI, показанный при подключении в ChatGPT, без wildcard.

```sh
wantedframe-mcp init --config /secure/config.json --pairing /secure/wantedframe-pairing.json
wantedframe-mcp serve --config /secure/config.json --data /secure/state
```

Сервис слушает только `127.0.0.1:18767`. Публичный адрес `https://YOUR_HOST/mcp` обслуживает существующий
HTTPS-прокси. В Caddy/Nginx добавляется отдельный hostname, не заменяется основной конфиг.
Настрой для `/ingest` лимит тела 24 MiB, отсутствие access-log тела/Authorization и общий rate limit.
Caddy внутри Docker не видит хостовый loopback: можно задать `listenUds=/run/wantedframe-mcp/web.sock`,
смонтировать только каталог сокета в прокси и выдать узкий групповой доступ. НЕ открывать приложение
на 0.0.0.0 и не ставить chmod 777 ради обхода.
Пошаговая изолированная установка, архив только из разрешённых серверных файлов и шаблоны прокси —
в [`deploy/README.md`](deploy/README.md). Скрипт подготовки не запускает сервис и не изменяет прокси;
конфиг, pairing и снимки не входят в серверный архив.
Файл `wantedframe-mcp.service` — шаблон; сначала создать пользователя без shell и каталог venv,
установить package, передать владение приватным конфигом этому пользователю. Не перезапускать общий VPS.

MCP OAuth принимает только числовой GitHub ID владельца. Upload token работает только для `/ingest`,
не позволяет читать аккаунт через MCP. В конфиге и pairing он секретный. На Windows WantedFrame
сохраняет подключение через защищённое хранилище ОС; при его отсутствии не пишет токен открытым текстом.
После импорта pairing удалить его незашифрованную транспортную копию на ПК/из Downloads по решению владельца.

## Чтобы ChatGPT знал о подключении

Имя приложения: **WantedFrame**.
Описание: **Мой аккаунт Warframe: инвентарь, количества ресурсов и валют, моды и их ранги,
сборки/конфигурации, мистификаторы, осколки, прогресс мастерства, производство, репутация,
рецепты и события. Начинай с get_account_overview, затем list_data_sections.**

Полный текст поведения в `wantedframe_mcp/server.py` — серверные MCP instructions, а не содержимое
инвентаря. Он запрещает путать неизвестное с нулём, старые данные со свежими и историю освоения с владением.

В настройках проекта ChatGPT можно закрепить:
> При вопросах о моём Warframe-аккаунте сначала используй подключённый WantedFrame.
> Сам выясняй доступные категории через get_account_overview/list_data_sections, не проси меня перечислять инструменты.
> Проверяй даты, неполные разделы и страницы; не отвечай об остатках по памяти.

MCP нужно один раз реально подключить и разрешить в используемом чате. Репозиторий сам по себе
не добавляет инструменты в ChatGPT; сервер не записывает весь аккаунт в постоянную память и не
отправляет сам сообщения в другие разговоры. Без MCP достаточно приложить ZIP целиком — внутри есть инструкция.

## Проверка и эксплуатация

Нужен один практический цикл: экспорт из реального аккаунта → ручная отправка → OAuth вход →
карта разделов → поиск одного ресурса → запись одного оружия `/configs/0/mods` → повторная синхронизация.
Сверить несколько значений с игрой; отсутствие данных не маскировать фикстурами. Русский OCR здесь не перестраивался.

На сервере остаются только текущий и предыдущий снимки (до 24 MiB каждый) плюс состояние OAuth.
Пароли, HTTP-тела и снимки не логируются. Автоматическое отключение в программе не отзывает копии,
уже переданные в ChatGPT или на VPS. Для отзыва: выключить синхронизацию, удалить подключение в
ChatGPT, заменить ingestToken/пересоздать pairing; для удаления аккаунтных данных остановить этот
сервис и удалить только его приватный `snapshots.json`. Не выполнять общую очистку Docker.

Старый snapshot не заменяет новый; курсоры закреплены за ревизией. Если ревизия уже вытеснена,
запрос завершается явной ошибкой, а не смешивает страницы. `get_world_state` независимо читает
фиксированные DE-адреса для ПК и помечает кеш устаревшим при сбоях.

Исходники и схема находятся в том же репозитории, приватных данных в нём быть не должно.
Основные зависимости зафиксированы частично; перед production оператор сохраняет точный `pip freeze`.
